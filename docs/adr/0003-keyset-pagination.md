# 0003. История сообщений листается keyset'ом, не OFFSET

Статус: принято · Заход 2 · [Р7]

## Контекст

История чата — живая лента: пока пользователь листает вверх, снизу приходят новые сообщения.
Страницы отдаются REST-эндпоинтом `GET /api/v1/conversations/{id}/messages`.

## Решение

Курсор — id последнего показанного сообщения:

```sql
select * from messages
where conversation_id = ? and id < :before
order by id desc
limit :n;
```

Без `before` отдаются последние N. Под запрос лежит композитный индекс
`(conversation_id, id desc)` из миграции `V3`.

## Последствия

Вставки между запросами страниц курсор не сдвигают: он привязан к строке, а не к порядковому
номеру. Глубина страницы не влияет на стоимость — индекс позиционируется сразу на нужный id.

Цена — курсор нельзя прыгнуть на «страницу 7»: листать можно только последовательно. Для
чата это не ограничение, для таблицы с номерами страниц было бы.

Фронт хранит минимальный показанный id и шлёт его в `before` кнопкой «загрузить ещё»; тот же
запрос дочитывает пропущенное после обрыва соединения.

## Альтернативы

**OFFSET/LIMIT.** На живой ленте дублирует и пропускает строки: пришли два сообщения — и
вторая страница сдвинулась. Плюс деградирует линейно по глубине, потому что PostgreSQL
читает и выбрасывает `offset` строк.
